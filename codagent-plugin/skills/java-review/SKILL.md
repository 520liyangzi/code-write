# Java Review

审查当前任务的完整 Java 变更，不加载原始规范全文，只使用已激活规则及其来源引用。

1. 获取完整变更集合；不要只检查最后一次编辑。
2. 运行最终规范检查和会话报告。若 Hook 已执行，仍需确认最终 diff 与最后一张检查回执一致。
3. 每个问题必须包含规则 ID、严重级别、文件位置、证据、建议和验证类型。
4. 区分确定性检查与 AI 判断。编译或测试通过不能替代规范检查。
5. 修复 blocker/major 后重新检查；规则库或检查器失败时不得报告“合规”。
6. 若没有命中专门规则，如实记录；不得把通用实践冒充公司要求。
7. Stop 返回待 AI 审查规则时，逐条对照最终 diff 完成语义审查，报告规则 ID 和结论后再请求结束；第二次 Stop 只表示 AI 自述已处理，不能描述成程序化验证。

最终摘要至少包含：

- 修改了哪些逻辑单元；
- 命中了哪些规则；
- 哪些单元已检索但无专门规范；
- 确定性检查、AI 审查、编译/测试各自结果；
- 自动修复过的问题与仍未解决的问题；
- 规则库版本和审计报告位置。

CodeGraph 仍是可选信息源：可用时用于影响分析，不可用时明确标记为跳过，不影响规范审查本身。
